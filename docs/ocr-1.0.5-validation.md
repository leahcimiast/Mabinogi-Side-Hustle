# 1.0.5 OCR 原始碼驗證（2026-10-13）

> 以下為各次修改完成時的開發驗證紀錄；1.0.5 發行資訊以 CHANGELOG.md 為準。

基準：`0de0bd2`（目前 1.0.4 分支 HEAD）。修正位於 `codex/1.0.5-item-ocr-accuracy`，尚未 commit 或發行，不含 EXE／ZIP。

## 原因與修正

提供的截圖中，蘋果汁品名在五種辨識中有四種正確，數量 7 的八種原始辨識均無有效讀值。既有完整字形補讀要求至少兩個字形，無法接受單位數。彩色圖示及上方反光也干擾一般數量輸入圖。

新增單位數專用的完整字形路徑：保留完整原始裁切中的所有有效字形，再以兩個位置（原位、向下 4px）、兩種白字亮度遮罩（160、180），各產生兩個 OCR 比例。八張圖取代原本八張，不額外增加正常流程的 OCR 輸入。四組位置／遮罩都須至少有一個有效讀值，所有數字讀值須一致且為 1–9。裁切不完整、首位數字仍存在、位置或遮罩不一致、OCR 衝突都不接受；失敗時維持待核，不用較弱的多數決覆蓋衝突。

原有多位數補讀仍預設至少兩個字形。品名、白名單、等級、加號、數量轉移、任務啟用及完成判定未修改。這是所有素材共用的數字處理，沒有蘋果汁專用別名。

共用 `white_mask` 用 Pillow 通道運算取代 Python RGB 逐像素迴圈，套用於完整字形、盤點去色補讀及領取數量輸入框；亮度／色差條件逐像素保持一致。數量輸入框保留原本不限制色差的條件。沒有把白字數字遮罩套用到中文字品名或任務追蹤。

## 比較方法

- 相同 Windows OCR、相同白名單及本機環境，完整執行 `StockVision.cells()`。
- 將本次附圖的遊戲區裁切為 `(0,25,1278,985)`，依支援解析度正規化為 1280 × 960；桌面及助手視窗不進 OCR。
- 本次附圖及六張既有保管箱截圖各執行三組前後比較，交替修改前／後順序；每次建立新的 OCR session。
- 計時包含品名、數量、所有補讀、圖片編碼及 OCR 往返，不含約 0.4 秒的 OCR session 啟動；另記錄批次數及輸入圖片數。
- 截圖與原始測量留在忽略的 `.local/`，沒有加入可提交檔案。全程只辨識既有圖片，沒有送出遊戲輸入。
