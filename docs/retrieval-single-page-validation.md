## 修改範圍

本輪產品程式碼僅修改 `app/automation.py` 的素材領取流程。新增狀態只存在目前 Runner 中，不寫入設定或進度檔。`withdrawal()` 每次開始都清除狀態。

- 目前畫面有唯一符合素材時，照原流程直接領取，不為建立單頁紀錄而捲動。
- 首次找不到素材時，保留原本向上歸頂及向下搜尋的有界重試。如果上、下整段均未觀察到位移，且再取得的保管箱畫面與控制區仍有效，才記住本次單頁狀態。
- 只要途中曾向上或向下移動，就不建立單頁紀錄；多頁邊界不能被當成單頁。
- 後續素材仍執行五種品名 OCR、局部補讀及候選／衝突檢查。找不到時，若單頁紀錄仍有效，直接列為待手動補領，不重複上下捲動，也不把未辨識當成已領取。
- 暫停後繼續、保管箱選擇器／分類列／搜尋篩選控制區改變時紀錄失效。數量、重量及物品選取區不參與控制區比對，正常領取不會使紀錄失效。
- 不快取或重用素材座標；仍以當次畫面的品名與格位選取素材。保留失去焦點、可用熱鍵／暫停按鈕、畫面與數量視窗、等級／加號、多堆疊及轉移記錄處理。

與本輪開始前逐檔比對，25 個受保護檔案未變：包括 UI、按鈕主題、輸入控制、`storage_scroll.py`、OCR、庫存盤點及其他 app 模組。`automation.py` 的任務交付方法也逐字保持不變。滾輪定位等待 0.25 秒、15 次輸入各 0.08 秒、結束等待 0.65 秒及兩個位置重試均未改動。

## 前後比較

使用本輪修改前的 `automation.py` 快照及修改後來源，執行相同 Runner／Journal 流程。使用靜態保管箱截圖、模擬的品名結果、畫面判定及輸入；實際執行原有 `scroll_page()`、位移判定與捲動次數邏輯，將等待記入虛擬時鐘，不送出遊戲輸入。

| 情境 | 滾輪輸入：前 → 後 | 固定等待：前 → 後 | 結果 |
| --- | --- | --- | --- |
| 單頁，1 種素材未辨識到 | 60 → 60 | 8.4 → 8.4 秒 | 同一素材待手動補領、零轉移 |
| 單頁，3 種素材未辨識到 | 180 → 60 | 25.2 → 8.4 秒 | 同三種待手動補領、零轉移 |
| 當前畫面找到 3 種素材 | 0 → 0 | 2.76 → 2.76 秒 | 同三種素材依序領取 |
| 單頁，1 種未辨識到、2 種找到 | 60 → 60 | 10.24 → 10.24 秒 | 同一種待補領、同兩種領取 |

三種未辨識素材的情境，首次確認後節省 **120 次滾輪輸入與 16.8 秒固定等待**，完整品名掃描輪數由 6 → 4；每次掃描仍保留五種方法及局部補讀。所有情境的領取紀錄、待補領素材集合、轉移次數及 pending 狀態一致。

首次建立單頁紀錄額外核對一次保管箱畫面。因此只有一種素材未辨識到時，沒有固定等待的節省，且增加一次畫面驗證成本。表格是流程模擬的固定等待，不含 Windows OCR、畫面擷取、遊戲動畫及伺服器耗時；不能解讀為實機總耗時或一般 OCR 準確率。

## 測試、審查與限制

完整來源測試 **375 項：374 通過、1 跳過**。跳過的是實際 F8 熱鍵／焦點監測測試，因 F8 已被其他程式占用。新增 12 項測試涵蓋單頁沿用、上下任一方向曾移動時拒絕單頁判定、最終畫面驗證、控制區與暫停失效、數量／重量變化、重新開始、當次座標、重複／加號衝突及辨識後停止。既有其他分頁、主題、OCR、捲動及轉移測試通過。

程式碼審查檢查狀態有效範圍、位移證據、畫面／暫停失效、未辨識素材的記錄、目前座標及安全邊界，未發現本輪修改的未解決問題。單頁紀錄是沿用有界上下無位移結果來省去重試，並不把滾輪未生效或 OCR 漏讀當成某素材確定不存在；未辨識素材仍列為人工核對。控制區出現額外視覺變化可能保守地使紀錄失效並重做確認。

尚待實機確認單頁、多頁、領取後列表重排及暫停恢復；本輪未執行遊戲自動化或修改 UI／按鈕樣式。
