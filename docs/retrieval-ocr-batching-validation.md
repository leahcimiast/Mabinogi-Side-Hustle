# 素材領取 OCR 批次化驗證（2026-10-13）

> 以下為各次修改完成時的開發驗證紀錄；1.0.5 發行資訊以 CHANGELOG.md 為準。

分支：`codex/1.0.5-retrieval-ocr-batching`。保留先前尚未提交的蘋果汁／單位數修正，只提供原始碼；未 commit、push、合併或打包。

## 修改

- 第一頁 `Runner.withdraw_one()` 以一個批次送出反相、彩色、灰階、二值化、加高裁切五張品名圖；不提早接受第一種方法的候選。
- 同一呼叫共用格位定位、原始品名裁切及灰階轉換。五種圖的像素、尺寸、排列與座標映射維持一致。
- 四種補充結果只供緊接著、同一張截圖的 `storage_names_retry()` 消耗一次。換圖、新請求、失敗或再次重試都不能沿用先前結果；沒有跨素材／跨捲動的座標快取。
- 保留原有局部補讀條件：若只有第一種方法讀到某格、四種補充方法都未讀到，仍局部補讀；不為了減少 OCR 張數而移除此檢查。
- `storage_scroll.py`、`input_control.py`、捲動次數與等待時間皆未修改；素材搜尋順序、白名單比對、模糊候選門檻、多堆疊、等級／加號衝突及轉移記錄規則未修改。
