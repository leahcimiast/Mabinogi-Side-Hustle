# 瑪奇M - 兼職小助手 v1.0.0

## 素材領取與任務交付

本版只提供核心批次操作：領取白名單所列 19 種素材，每種任務的需求乘以 3；玩家自行移動到佈告欄後，依「任務交付」頁設定逐一交付，預設每種 3 次。

領取／交付流程不掃描卷軸或素材持有數量，不扣除背包已有素材。另提供獨立的庫存盤點除錯功能。蜘蛛絲任務使用蜘蛛網，高級原木+ 保留 +。此版完整實機批次仍待驗證；辨識不明時會停止。

## 獨立庫存盤點

主視窗新增「庫存盤點」分頁，與領取及交付流程分開，不修改批次進度或交付次數。

1. 在遊戲開啟「公用保管箱 → 全部」，搜尋篩選也保持「全部」，關閉物品提示與數量視窗。
2. 選擇 **1–6 個交付循環**。此處 **1 循環＝每種白名單任務完成 3 次**，預設白名單為 57 次交付；6 循環為每種 18 次。需求由白名單每次用量加總計算，保留蜘蛛絲／蜘蛛網及素材名稱中的 `+`。
3. 按「盤點公用保管箱」，倒數期間會自動切回遊戲。程式回到清單頂端後，每輪以實測 540 px（約 4.4 列）為捲動目標再做 OCR；若已超過四列且下一格滾輪預估會超出重疊上限，可稍早辨識；到邊界時可提早停止。捲動期間只暫存及對齊左側物品畫面，不做 OCR；批次完成後剔除多餘畫面，再辨識覆蓋全程所需的重疊頁面，只讀取左側保管箱格位與左上方必要的分類控制；右側背包及其他區域不做 OCR。
4. 表格顯示「素材、需要、已辨識庫存、還缺」，數字不加「待核」後綴。已辨識數量足夠為綠色列，不足為紅色列；掃描中或辨識不完整時，紅色代表目前辨識量不足，缺額仍可能高估。不同格位的相同素材會加總，以畫面位移對齊去除捲動重疊，不用重複品名判斷到底。同一格一旦確認品名及數量，本次盤點會保留該數值，後續空白或不同 OCR 不覆蓋；尚未確認的格位可由較清楚的後續畫面補齊。停止後可切換循環數，直接重新計算需求。
5. 「待核」表示依已辨識庫存估算的缺額，可能高估；名稱／數量不明、清單未確認到底或中途停止時，不宣稱缺額已確認。已辨識數量足以支應所選循環時可直接顯示缺額 0；其餘只有清單覆蓋完整、相關辨識無疑義時，才顯示確認的缺額。空白數量不當成 1。
6. 「複製盤點結果」可複製表格；本機除錯報告也會記錄掃描及結果。結果只是有時間標記的快照，領取／整理庫存後請重新盤點。

盤點只擷取畫面與捲動，不點選素材、不領取、不啟用任務，也不改變原有兩個掃描流程。與其他操作共用可設定熱鍵、暫停／繼續、前景及 1280 × 960 檢查，同一時間只允許一項作業。手動暫停後繼續會保留目前盤點步驟與累計；因錯誤停止後重新盤點才從頂端重新計數。

目前使用分次滾輪事件（每次間隔 0.08 秒），避免遊戲把單次大滾輪數值限制成一次小移動；持續檢查實際位移，依實測位移調整每段 1–16 格滾輪，目標約 540 px 再做下一輪 OCR，分段暫存畫面保持重疊，比對六欄差異的中位數以降低局部發光動畫干擾，並用反向移動再返回確認清單邊界。若上下皆不能捲動（包括僅有一頁的情況），會保留未完成狀態，避免把未生效的滾輪當成到底。僅盤點功能增加裁切品名重試及唯一模糊比對（除錯紀錄列出原文 → 完整素材名），保留羊毛等級、料理／原料與 `+` 差異；數量由多方法讀值的一致性判斷，平票仍待核對。使用 2026-09-18 玩家提供的三張截圖，離線累計 19 種素材數量全部符合人工讀值。實機全清單捲動、不同庫存排列及空保管箱仍待驗證；截圖驗證不代表實機耗時。

## 介面與操作

GUI 調整：主視窗預設寬度縮為 550（本次由 688 再縮窄約 20%），高度維持 850；只有展開除錯面板時加寬為 890，收合後恢復窄版。以上尺寸會隨 DPI 縮放。任務交付的「−」為紅色、「＋」為綠色，兩欄固定窄寬、不隨視窗拉開間距，點擊仍沿用原有次數調整與儲存方式。開始素材領取或任務交付時會切到對應分頁顯示進度，切換分頁不改變視窗大小。庫存盤點分頁上方增加與頂部同色的黃色提示：「注意事項: 盤點前開啟「公共保管箱 → 全部」」。

主視窗新增「素材領取／任務交付」分頁。「任務交付」顯示各任務的預計、已完成與剩餘次數，以及整批剩餘總數。點選每列「−／＋」立即減少或增加剩餘次數並儲存，不必輸入數字或按 Enter。預設 3，設為 0 可略過。可在停止後修改，保留已完成紀錄；執行中、有已啟用任務或中斷結果待核對時禁止修改。每次新批次／重開仍恢復每種 3 次。交付設定不改變素材領取量（仍為每種三次需求）；增加交付次數前請自行備齊素材。

交付開啟背包並進入「道具」後，將頂部篩選列由右向左完整拖曳一次，使分類捲到最右端；等待移動結束後，點擊 1280 × 960 遊戲內容內固定的「任務」位置 (1189, 140)。這一步不做任務分類文字 OCR、白色選取驗證或 E 鍵切換；搜尋卷軸時也不再重讀分類。道具主分類與後續卷軸辨識仍保留。卷軸只讀名稱格位，以冒號後的名稱比對白名單，允許唯一且足夠相近的 OCR 結果，不要求卷軸前綴逐字正確。保留 `+` 與等級差異、蜘蛛絲卷軸／蜘蛛網素材對應，不重讀堆疊數量或物品提示名稱，不彈出名稱確認。仍驗證使用按鈕、啟用後唯一回報狀態，以及交付完成；初始接手既有任務時身份不明會停止。

視窗名稱為「瑪奇M - 兼職小助手 v1.0.0」。每次開啟直接建立新批次，進度從零開始；按「重置」一次即可重新開始，不再要求第二次確認。舊進度封存在本機 `batch-history`，不自動恢復。執行中須先暫停，待目前工作停止後才能重設。

搜尋素材會分次送出滾輪並檢查素材區是否真的移動。OCR 名稱重複或空白不再作為到底依據；未找到素材時持續向下捲動。每次送出 15 格滾輪（原本的 5 倍）後再辨識；兩個游標位置重試均沒有畫面位移才停止，並說明可能已到底或遊戲未接受滾輪。超過安全上限會報告尚未確認到底，不假裝已完整搜尋。品名擷取會依捲動後的文字列位置重新定位。

## 下載與版本

從私人儲存庫的 [v1.0.0 Release](https://github.com/leahcimiast/Mabinogi-Side-Hustle/releases/tag/v1.0.0) 下載 ZIP 與 `.sha256`。完整解壓縮後執行 EXE，不要只複製 EXE；不需要安裝 Python 或 Excel。請保留原有 `%LOCALAPPDATA%\MabinogiSideHustle` 資料夾，熱鍵設定與本機紀錄仍使用同一位置；啟動會封存舊批次並建立新批次。

可用 PowerShell `Get-FileHash -Algorithm SHA256 -LiteralPath '下載的ZIP路徑'` 與 `.sha256` 內容比較。

## 安裝與開始

1. 關閉舊版助手，解壓縮 `MabinogiAssistant-1.0.0-*.zip`，保留整個資料夾及 `_internal`，執行 `MabinogiAssistant.exe`。
2. 使用 Windows 10/11 x64、Windows PowerShell 5.1，並安裝繁體中文（台灣）的 Windows OCR 語言元件。不需要 Python 或 Excel。
3. 將遊戲內容設為 **1280 × 960**，開啟 **公用保管箱 → 全部**，關閉物品提示。玩家準備每種卷軸 3 張、足量素材及背包負重。
4. 在主畫面按 **「開始／繼續領取」**，倒數期間會自動切回遊戲。程式自動檢查遊戲視窗、前景、尺寸及預期畫面，不需要手動偵測、截圖或確認 UI。
5. 玩家已備齊素材時，可直接在佈告欄旁開始交付，不需先執行領取。關閉對話，背包材料頁可保持開啟。依主畫面的「交任務前請先前往佈告欄並關閉對話視窗」提示準備後，按 **「開始／繼續交付」**，倒數期間會自動切回遊戲。

## 單一主畫面

- **素材清單**：每種需求量、待領取／處理中／已領取／輸入中斷。正在處理的素材會突出顯示。
- **批次進度**：即時更新領取種類數（19）及交付次數（57），不需按更新。
- **目前作業**：目前素材／任務、需求量、步驟、執行時間、距上次回報時間。
- **停止原因**：獨立顯示並保留最後失敗原因，不會被一般進度訊息蓋掉。
- **除錯紀錄**：預設收合，主視窗採窄版配置（依 DPI 與提示文字調整最小寬度）。按「顯示除錯紀錄」展開右側面板，再按「隱藏除錯紀錄」縮回；收合時仍持續記錄，目前作業、停止原因與核對操作始終可見。紀錄顯示搜尋頁次、辨識到的名稱、數量輸入與按鈕就緒狀態、確認領取、交付及錯誤，附時間戳。畫面保留最近約 2,000 行；完整文字紀錄存於本機。
- **暫停／繼續**：預設 F8，上方選單可改為 F1–F12，設定儲存在本機；執行中不可改鍵。按相同熱鍵或按鈕可暫停／繼續同一工作，繼續先自動切回遊戲。暫停期間不要改變遊戲頁面或手動轉移物品。若新熱鍵已占用，保留原熱鍵。失去焦點、關閉程式或結果不明仍會停止；不可自動越過中斷核對。手動暫停時可按「重置」取消目前工作，待工作停止後建立新批次。

沒有圖片預覽、Excel 載入、手動 OCR 工具、單次 I 鍵測試或額外批次視窗。交付前提示與中斷核對顯示在主畫面內，新批次按一次直接建立。

## 領取與交付的確認方式

領取沿用本次清單辨識與選取格位的品名，不再重讀物品提示名稱或要求人工名稱確認。點選數量欄後清除預設 1，再輸入需求量。輸入前仍確認數量視窗；輸入後依玩家設定不再讀回數字，僅檢查右下固定綠色移至背包按鈕區域，無需文字 OCR，按鈕就緒便送出。因此不會偵測遊戲自行限制輸入數量的情況。送出後確認回到清單再處理下一項，不比較庫存差額。

選取已辨識卷軸後，以固定位置及綠色範圍確認「使用」按鈕，不再辨識按鈕文字或重讀卷軸名稱；確認後點擊按鈕中央。

追蹤任務的 OCR 若漏掉「取得／製作」的全部或部分字元（例如「得鐵礦石」），只在完整品名位於標題列、且其下方同區塊有回報文字時接受；持有數量列或其他任務文字不算。開始交付先檢查現有追蹤任務，不先開背包。若能唯一確認為白名單內可回報任務（不限清單第一項），先交付這張，確認通關後計入對應任務一次，再按原清單順序繼續。例如羊毛預設 3 次，先完成已啟用的一張後剩餘 2 次，鐵礦石次數不變。若該任務剩餘設為 0，僅增加並完成這一張已啟用任務；不額外開卷軸。全部設為 0 仍可按開始交付檢查既有任務。非白名單、身份不明或尚不可回報時停止。

交付時每次只啟用一張已辨識卷軸，沿用批次身份並核對唯一回報狀態，開啟自動放入並確認提交按鈕就緒（不再核對遊戲已篩選的素材名稱），再提交。交付與對話階段只辨識控制與對話的小區域，減少每步等待。確認底部大型綠色按鈕、關閉完成畫面及回報追蹤消失後，才處理下一張。

## 中斷與新批次

- 進度存在 `%LOCALAPPDATA%\MabinogiSideHustle\fixed-batch.json`；報告存在同目錄的 `reports`。除錯紀錄顯示目前紀錄檔位置。
- 如果領取點擊本身送出失敗，或任務啟用／交付中斷時結果不明，主畫面會顯示 **「中斷結果待核對」**。先對照遊戲並勾選確認，再選「確認已成功」或「確認未發生」。不確定時保持暫停，不會自動重送。
- 成功提交任務的核對包含完成畫面已關閉、回報追蹤消失。不要只因已按提交就標記成功。
- 按 **「重置」** 一次即封存舊紀錄並歸零，下一批重新領取全部需求。這不會撤銷遊戲內已領取的素材或已啟用的任務。
- 同一次開啟期間，手動暫停用相同熱鍵繼續原步驟；錯誤停止後可按對應階段重新檢查，已確認完成的項目會跳過；關閉重開則從新批次開始。

## 已知限制

- 開始前請確認佈告欄任務已正確追蹤；OCR 無法保證發現隱藏、未追蹤或未讀出的既有任務。

- 領取流程不使用盤點結果，不會計算剩餘負重或合併不足的多堆疊；材料缺少或確認按鈕未就緒且尚未領取時列入手動補領；不再偵測輸入被遊戲限制的數量。無法確認可安全返回保管箱的畫面仍會停止。
- 格位、捲動及按鈕依提供的 1280 × 960 錄影實作。完整 19 種實機領取、料理任務追蹤及 57 次交付仍未完成驗證。
- 前景操作為基準。背景輸入未驗證、未啟用；没有注入、讀寫遊戲記憶體或繞過保護機制。
- 圖片、紀錄及進度只留在本機，沒有自動上傳。

## 玩家確認名稱並繼續

當物品提示中有可辨識的素材名稱，但與預期名稱不同時，主畫面會詢問「OCR 讀到的名稱」是否就是預期素材。按「是，記住此名稱並繼續」後，本機儲存此對應，倒數 3 秒並自動切回遊戲；保持目前物品提示／數量視窗，程式會重新擷取畫面，從同一步驟繼續，不重開批次、不重領已完成素材。選「不是／不確定」則跳過此素材並列入手動補領；按 F8 則停止。等待回答最長 5 分鐘。


搜尋「羊毛」只接受完整「羊毛」名稱，不使用模糊候選。「高級羊毛」、OCR 截短的「級羊毛」及其他非完全相同的名稱會跳過，繼續向下搜尋；不會要求玩家把它們確認為羊毛。舊的非完全相同羊毛名稱記憶也不再使用，其他素材規則維持原樣。

## 名稱候選與手動補領

- 未找到、候選不唯一、數量驗證失敗等尚未送出領取的項目，列入「待手動補領」，並在確認返回保管箱後接著處理下一種。
- 主畫面與本機報告列出待補領名稱、完整需求量及原因。已跳過的素材不會自動重試；手動補足後，選取清單中的素材並按「已手動補足選取素材的全部數量」。補領紀錄不限制任務交付；交付假設玩家已備齊素材。
- F8、失去焦點、未知畫面或領取已送出但結果不明仍會停止；不會盲目關閉未知視窗或將不確定的轉移列為未領取。

## 素材 OCR 重試與注意事項

- 頂部「注意事項:」以紅色 12 點粗體顯示；「新批次」位於「開始／繼續領取」左側。
- 本頁未找到完整素材名時，先嘗試彩色、灰階、自動對比、二值化及加高裁切，再決定候選或換頁。原本的反相放大辨識仍為第一步。
- 數量欄原辨識無結果時，再嘗試另外兩種亮度門檻；不同數值互相衝突時保持不明，不以預期數量猜測答案。
- 以上是目前本機 Windows OCR 的有限重試流程，並非保證所有 OCR 引擎或所有處理方式都能辨識成功。不新增雲端辨識或上傳畫面。仍保留 F8、前景檢查、重試期限與手動補領。

## 首次多方法掃描與除錯紀錄

- 保管箱每頁首次掃描固定執行反相、彩色、灰階、二值化、加高裁切五種處理，首種方法已找到目標也不略過其餘方法。
- 任務卷軸每格以反相、綠色通道、彩色、灰階、二值化五種方法辨識。原本漏讀的格位亦參與；不同方法對應到不同白名單卷軸時標為衝突，不啟用。
- 保管箱與任務交付畫面使用原尺寸彩色，加上 2 倍彩色、灰階、反相、二值化，共五種 OCR。涵蓋任務分頁、使用按鈕、追蹤／回報、提交、自動放入與通關確認。仍保留原畫面的顏色條件、任務順序、確認關卡及停止機制。
- 除錯面板的「複製全部」複製本次完整紀錄檔，包含已超過畫面行數上限的紀錄；剪貼簿為純文字。
- 開始搜尋、已領取與領取確認顯示綠底深綠字；待手動補領及停止原因顯示紅底深紅字。仍在搜尋的未找到訊息保持原色。收合面板時仍持續記錄並保留標色。

## 領取速度與黃豆辨識修正

先在當前頁尋找下一項素材，找不到才回頂搜尋；不再每種素材一律回頂。領取畫面以裁切區域進行五方法 OCR；領取前沿用初次辨識品名，只核對數量視窗與實際輸入量。格位掃描加入 2 倍倍率，並對無文字格位使用獨立 2 倍裁切，處理黃豆在大型 OCR 圖集中漏讀的情形。領取前不會沿用前一項素材的格位座標。

離線測量與程式碼審查見 [PERFORMANCE_REVIEW.md](PERFORMANCE_REVIEW.md)。整批縮短至少 2/3 的目標尚待實機計時，不能由單張截圖測速直接保證。

物品選取後，先以小範圍 OCR 確認中央綠色「移至背包」按鈕已顯示，才送出一次 Space 開啟數量框，避免提示動畫尚未完成時按鍵被忽略。按鍵送出後不盲目重送；領取前只核對數量視窗與實際輸入量。

素材候選依物品格位置比較：同一格經不同 OCR 方法讀出的近似名稱不會互相排斥。正常執行時隱藏「中斷結果待核對」；只有工作停止且動作結果未明時才顯示，避免重複領取。

數量欄點選後額外等待 0.5 秒，清除／逐字輸入間隔為 0.15 秒。取消未領取的數量視窗後，最多重新觀察 6 次；同一種數量視窗或物品提示不重複送 Esc。失敗紀錄會列出公用頁、背包標題及視窗標記，便於查出暫時辨識失敗。

領取數量核對通過並成功送出領取點擊後，立即記錄「已領取」，依玩家設定假設已入背包，不驗證實際庫存結果。後續只等待清單供下一項操作使用；逾時或暫停不會撤回已領取標記，也不會自動重領。任務交付仍需確認完成。
## 深色桌面介面

採用炭灰底色、柔和文字、圓角按鈕與輸入框，以及明確的滑入、焦點、選取與停用狀態。中文字型優先使用 Microsoft JhengHei，數字輸入使用 Segoe UI；未安裝時使用可用字型。

配色、字型、間距集中於 `app/desktop_theme.py`。保留原本 Tk/ttk 元件、callbacks、鍵盤事件及狀態控制，圓角由既有 Pillow 相依套件在啟動時產生，不需增加 CustomTkinter 或 ttkbootstrap，也不需額外圖片資產。保留新版任務表格的行內剩餘次數編輯流程，未加入額外的套用按鈕。

一般視窗基準為 860 × 850，除錯展開寬度為 1200；尺寸依啟動時 Tk 縮放與螢幕大小調整。底部 F8 狀態與紀錄位置優先保留空間。設定、批次紀錄及自動化行為不因外觀而變更。

PR #3 深色主題已與最新素材／任務分頁、行內剩餘次數編輯及快速分類切換整合；保留既有元件與事件流程。多螢幕間切換 DPI 與遊戲內完整批次仍需實機驗證。

除錯紀錄區採較大文字區，按鈕、頁籤與上方區塊改為緊湊高度；複製與清除名稱按鈕併列。交付前提示不需勾選，中斷結果核對仍保留。提交後以底部大型綠色確認按鈕的位置、寬高及綠色覆蓋率判定通關，不再辨識通關標題或任務名稱。仍需關閉結果畫面並確認回報追蹤消失，才記入完成。

追蹤名稱支援「取得／製作／尋找」前綴；「尋找蜘蛛網」沿用蜘蛛絲卷軸對應蜘蛛網的白名單映射。

交付循環的任務追蹤 OCR 只讀右上四分之一，採原色及 2 倍原色。啟用後僅辨識此區；開始／完成後另讀左下小區域確認回到遊戲。已辨識卷軸後的「使用」採固定位置與綠色按鈕範圍，不再讀文字。任務分類、自動放入、提交、通關確認沿用固定位置操作；任務身份、卷軸品名與對話畫面仍保留必要的局部辨識。

助手使用已辨識的卷軸後，任務種類沿用批次紀錄，不再核對追蹤標題文字。右上出現「回報任務佈告欄」或「向任務佈告欄回報」即點回報位置交付；若出現兩個不同回報位置則暫停。起始接手沒有批次身份的既有任務仍需辨識名稱以正確計數。完成仍須確認綠色通關按鈕、關閉結果畫面並確認回報消失。

搜尋後找不到目前白名單卷軸時，助手會略過該任務全部剩餘次數並記錄原因，留在同一任務背包頁繼續下一種。已完成次數不變，略過不算完成；其他任務數量不變。F8、失去焦點、辨識歧義或已啟用／交付結果不明仍暫停。

找不到卷軸時最多搜尋 6 輪。每次捲動後先比較名稱區的影像變化，忽略圖示／堆疊動畫；未移動時换一個游標位置重試一次，仍未移動便略過，不對相同畫面重跑 OCR。極長任務清單超過此搜尋範圍的項目可能被略過，可整理背包後重新設定剩餘次數。

交付開始時若已在背包（含材料分類），助手辨識底部道具分類後直接切到任務，不按 I 關閉重開。搜尋不到而略過卷軸時保留任務頁，僅將清單捲回頂端搜尋下一種。使用卷軸使背包關閉後，下一輪才重新開啟。

若已辨識到右上的佈告欄回報項目，啟動時不再因左下聊天提示漏字而阻擋；仍辨識既有任務身份以正確計數。回報或世界提示漏讀時僅重讀對應小區域。提交後只檢查通關按鈕及對話區，輪詢間隔為 0.1 秒，避免重讀已離開的交付畫面。

介面不再顯示上方「待開始」狀態列及進度條；保留數量摘要、目前作業與停止原因。領取／交付表格隨目前項目捲動；盤點表格保留捲動位置，新增確認數量時移至最新素材。盤點紀錄列出每段實測位移；以約 540 px 為物品 OCR 間距（到邊界可提前）。盤點專用 OCR 補入截圖重現的完整品名誤讀「洋蒽 → 洋蔥」及「恘恘菇 → 咻咻蘑菇」，玩家已核准單字「洋」對應洋蔥。修改原始碼後需重新啟動程式才會生效；既有打包 EXE 不會自動更新。

「目前作業」的「耗時」適用於素材領取、任務交付與庫存盤點，從按下開始計算（包含三秒倒數及中途等待），執行中持續更新，完成或停止後保留最終分鐘／秒數；下一次開始重新計時。盤點對仍未確認的短品名追加同格位 2 倍裁切重試，保留已確認堆疊不覆蓋的規則。

開始／繼續領取、交付與盤點，以及名稱確認後的倒數，會對唯一已驗證的遊戲視窗請求一次前景切換（最小化時還原）。Windows 拒絕切換、多個遊戲視窗或 F8 取消時停止，不強行重試；作業期間失去前景仍停止。「目前作業」只顯示玩家提示；品名比對、OCR 與捲動位移細節保留在除錯面板。底部 F8／本機紀錄說明、紀錄檔路徑與複製通知移至除錯紀錄。循環選單停用時仍使用深色背景與可讀文字。盤點品名候選包含「黄豆 → 黃豆」，不接受單字或帶加號／等級的不同品名。

## 1.0.0 介面及操作更新

頂部只保留黃色「注意事項: 遊戲解析度 1280 × 960」；領取按鈕與保管箱提示移到「素材領取」分頁。任務佈告欄提示移到「任務交付」統計下方，維持黃色；次數調整提示中的 − 為紅色、＋ 為綠色。不再顯示每種預設三次的頂部說明，預設次數行為不變。移除手動補足確認按鈕，保留補領清單。手動暫停保留執行位置，畫面等待期限扣除暫停時間；耗時欄仍包含暫停時間。實機綠色按鈕領取與熱鍵繼續仍待驗證。

暫停會在下一個輸入檢查點生效；進行中的短滑鼠拖曳會先放開按鍵再暫停，避免滑鼠保持按住。

頂部新增「建議將遊戲鏡頭控制轉為手動鏡頭」。領取／交付計數已移入「目前作業」，只在該功能執行或手動暫停時顯示；閒置與盤點時不顯示。除錯面板移除清除名稱記憶按鈕，OCR 別名集中於 `app/ocr_aliases.py`，供素材領取、卷軸交付與庫存盤點共用。玩家已核准「洋 → 洋蔥」，亦支援「洋蒽／洋悳 → 洋蔥」；僅對完整 OCR 讀值套用，不做任意字串替換，不忽略等級或加號。卷軸未辨識品名會對同格位追加局部彩色／灰階重讀。
