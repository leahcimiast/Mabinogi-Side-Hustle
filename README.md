# 瑪奇M - 兼職小助手

## 素材領取與任務交付

本版只提供核心批次操作：領取白名單所列 19 種素材，每種任務的需求乘以 3；玩家自行移動到佈告欄後，逐一完成每種任務 3 次。

不掃描卷軸或素材持有數量，不扣除背包已有素材。蜘蛛絲任務使用蜘蛛網，高級原木+ 保留 +。此版完整實機批次仍待驗證；辨識不明時會停止。

## 最新原始碼（尚未打包）

視窗名稱為「瑪奇M - 兼職小助手」。每次開啟直接建立新批次，進度從零開始；按「新批次」一次即可重新開始，不再要求第二次確認。舊進度封存在本機 `batch-history`，不自動恢復。執行中須先暫停，待目前工作停止後才能重設。

搜尋素材會分次送出滾輪並檢查素材區是否真的移動。OCR 名稱重複或空白不再作為到底依據；未找到素材時持續向下捲動。每次送出 15 格滾輪（原本的 5 倍）後再辨識；兩個游標位置重試均沒有畫面位移才停止，並說明可能已到底或遊戲未接受滾輪。超過安全上限會報告尚未確認到底，不假裝已完整搜尋。品名擷取會依捲動後的文字列位置重新定位。

關閉舊版助手後，在 PowerShell 執行：

```powershell
Set-Location -LiteralPath 'D:\Projects\Personal Projects\Mabinogi Side Hustle'
& '.\.venv\Scripts\python.exe' '.\main.py'
```

## 安裝與開始

1. 關閉舊版助手，解壓縮 `MabinogiAssistant-0.2.2-*.zip`，保留整個資料夾及 `_internal`，執行 `MabinogiAssistant.exe`。
2. 使用 Windows 10/11 x64、Windows PowerShell 5.1，並安裝繁體中文（台灣）的 Windows OCR 語言元件。不需要 Python 或 Excel。
3. 將遊戲內容設為 **1280 × 960**，開啟 **公用保管箱 → 全部**，關閉物品提示。玩家準備每種卷軸 3 張、足量素材及背包負重。
4. 在主畫面按 **「1 開始／繼續領取」**，3 秒內切回遊戲。程式自動檢查遊戲視窗、前景、尺寸及預期畫面，不需要手動偵測、截圖或確認 UI。
5. 全部領取完成後，玩家自行移動到佈告欄旁並關閉背包／對話。勾選主畫面的交付前確認，再按 **「2 開始／繼續交付」**，3 秒內切回遊戲。

## 單一主畫面

- **素材清單**：每種需求量、待領取／處理中／已領取／結果待核對。正在處理的素材會突出顯示。
- **批次進度**：即時更新領取種類數（19）及交付次數（57），不需按更新。
- **目前作業**：目前素材／任務、需求量、步驟、執行時間、距上次回報時間。
- **停止原因**：獨立顯示並保留最後失敗原因，不會被一般進度訊息蓋掉。
- **除錯紀錄**：預設收合，主視窗為 660 × 720。按「顯示除錯紀錄」展開右側面板，再按「隱藏除錯紀錄」縮回；收合時仍持續記錄，目前作業、停止原因與核對操作始終可見。紀錄顯示搜尋頁次、辨識到的名稱、數量輸入與读回結果、確認領取、交付及錯誤，附時間戳。畫面保留最近約 2,000 行；完整文字紀錄存於本機。
- **暫停（F8）**：按鈕或 F8 停止目前操作；失去遊戲焦點也會暫停，不自動搶回焦點。重新開始必須按對應階段按鈕。

沒有圖片預覽、Excel 載入、手動 OCR 工具、單次 I 鍵測試或額外批次視窗。交付前確認與中斷核對在主畫面內完成，新批次按一次直接建立。

## 領取與交付的確認方式

領取時先核對物品提示中的完整名稱，再以 Ctrl+A、Backspace 清除預設的 1，輸入需求量，例如 60。程式只讀回剛輸入的欄位，不讀庫存數量。辨識不明時最多重新擷取三次，分別記錄素材名稱、數量視窗及數字的核對結果；期間不重輸或確認。讀到明確不符的數字立即停止。輸入值不符或三次仍看不清時不會按下領取；確認後等待返回保管箱再記錄進度，沒有獨立比較庫存前後差額。

交付時每次只啟用一張卷軸，核對追蹤任務與回報狀態，確認素材名稱、自動放入及提交按鈕就緒，再提交。確認通關身份、關閉完成畫面及回報追蹤消失後，才處理下一張。

## 中斷與新批次

- 進度存在 `%LOCALAPPDATA%\MabinogiSideHustle\fixed-batch.json`；報告存在同目錄的 `reports`。主畫面底部顯示目前紀錄檔位置。
- 如果中斷時動作結果不明，主畫面會顯示 **「中斷結果待核對」**。先對照遊戲並勾選確認，再選「確認已成功」或「確認未發生」。不確定時保持暫停，不會自動重送。
- 成功提交任務的核對包含完成畫面已關閉、回報追蹤消失。不要只因已按提交就標記成功。
- 按 **「新批次」** 一次即封存舊紀錄並歸零，下一批重新領取全部需求。這不會撤銷遊戲內已領取的素材或已啟用的任務。
- 同一次開啟期間，暫停後可按對應階段繼續，已確認完成的項目會跳過；關閉重開則從新批次開始。

## 已知限制

- 不會計算庫存總量、剩餘負重或合併不足的多堆疊；材料缺少、輸入被限制或名稱驗證失敗且尚未領取時列入手動補領。無法確認可安全返回保管箱的畫面仍會停止。
- 格位、捲動及按鈕依提供的 1280 × 960 錄影實作。完整 19 種實機領取、料理任務追蹤及 57 次交付仍未完成驗證。
- 前景操作為基準。背景輸入未驗證、未啟用；没有注入、讀寫遊戲記憶體或繞過保護機制。
- 圖片、紀錄及進度只留在本機，沒有自動上傳。

## 玩家確認名稱並繼續

當物品提示中有可辨識的素材名稱，但與預期名稱不同時，主畫面會詢問「OCR 讀到的名稱」是否就是預期素材。按「是，記住此名稱並繼續」後，本機儲存此對應，倒數 3 秒供玩家切回遊戲；保持目前物品提示／數量視窗，程式會重新擷取畫面，從同一步驟繼續，不重開批次、不重領已完成素材。選「不是／不確定」則跳過此素材並列入手動補領；按 F8 則停止。等待回答最長 5 分鐘。

名稱記憶只適用於有「材料」標示的物品提示，不能取代每次數量核對；空白、歧義、其他白名單素材或不同 + 的名稱不自動放行。新批次及重開程式保留名稱記憶，存於本機 `name-memory.json`。可展開除錯紀錄，於停止後按「清除已記住的名稱」。如果只有數字讀取失敗，不會用名稱確認略過數量驗證。

搜尋「羊毛」只接受完整「羊毛」名稱，不使用模糊候選。「高級羊毛」、OCR 截短的「級羊毛」及其他非完全相同的名稱會跳過，繼續向下搜尋；不會要求玩家把它們確認為羊毛。舊的非完全相同羊毛名稱記憶也不再使用，其他素材規則維持原樣。

## 名稱候選與手動補領

- 「洋蒽」可作為「洋蔥」的候選，先開啟物品提示核對。如果提示仍讀成洋蒽，詢問玩家是否為洋蔥；確認後記住並接續操作。這不改變羊毛必須完全相符的限制，也不放寬其他名稱的相似度門檻。
- 未找到、候選不唯一、名稱／數量驗證失敗等尚未送出領取的項目，列入「待手動補領」，並在確認返回保管箱後接著處理下一種。選「不是／不確定，跳過此素材」也會列入清單，倒數 3 秒切回遊戲後繼續。
- 主畫面與本機報告列出待補領名稱、完整需求量及原因。已跳過的素材不會自動重試；手動補足後，選取清單中的素材並按「已手動補足選取素材的全部數量」。全部備齊才開放任務交付。
- F8、失去焦點、未知畫面或領取已送出但結果不明仍會停止；不會盲目關閉未知視窗或將不確定的轉移列為未領取。

## 素材 OCR 重試與注意事項

- 頂部「注意事項:」以紅色 12 點粗體顯示；「新批次」位於「1 開始／繼續領取」左側。
- 物品提示以「獲得方法」位置與其上方的標題位置核對名稱，不再一律要求料理名稱下方出現「材料」。仍核對所選物品，避免領取不同等級或不同 + 的素材。
- 本頁未找到完整素材名時，先嘗試彩色、灰階、自動對比、二值化及加高裁切，再決定候選或換頁。原本的反相放大辨識仍為第一步。
- 提示名稱讀不清時，先做獨立裁切、彩色 3 倍、灰階 2 倍、反相 3 倍與二值化 3 倍 OCR，再使用玩家名稱記憶／詢問玩家。各方法得到不同等級、不同 + 或其他白名單素材時，不自動放行。
- 數量欄原辨識無結果時，再嘗試另外兩種亮度門檻；不同數值互相衝突時保持不明，不以預期數量猜測答案。
- 以上是目前本機 Windows OCR 的有限重試流程，並非保證所有 OCR 引擎或所有處理方式都能辨識成功。不新增雲端辨識或上傳畫面。仍保留 F8、前景檢查、重試期限與手動補領。

## 首次多方法掃描與除錯紀錄

- 保管箱每頁首次掃描固定執行反相、彩色、灰階、二值化、加高裁切五種處理，首種方法已找到目標也不略過其餘方法。
- 任務卷軸每格以反相、綠色通道、彩色、灰階、二值化五種方法辨識。原本漏讀的格位亦參與；不同方法對應到不同白名單卷軸時標為衝突，不啟用。
- 保管箱與任務交付畫面使用原尺寸彩色，加上 2 倍彩色、灰階、反相、二值化，共五種 OCR。涵蓋任務分頁、使用按鈕、追蹤／回報、提交、自動放入與通關確認。仍保留原畫面的顏色條件、任務順序、確認關卡及停止機制。
- 除錯面板的「複製全部」複製本次完整紀錄檔，包含已超過畫面行數上限的紀錄；剪貼簿為純文字。
- 開始搜尋、已領取與領取確認顯示綠底深綠字；待手動補領及停止原因顯示紅底深紅字。仍在搜尋的未找到訊息保持原色。收合面板時仍持續記錄並保留標色。

## 領取速度與黃豆辨識修正

先在當前頁尋找下一項素材，找不到才回頂搜尋；不再每種素材一律回頂。領取畫面以裁切區域進行五方法 OCR；仍在確認領取前核對完整素材名及實際輸入量。格位掃描加入 2 倍倍率，並對無文字格位使用獨立 2 倍裁切，處理黃豆在大型 OCR 圖集中漏讀的情形。領取前不會沿用前一項素材的格位座標。

離線測量與程式碼審查見 [PERFORMANCE_REVIEW.md](PERFORMANCE_REVIEW.md)。整批縮短至少 2/3 的目標尚待實機計時，不能由單張截圖測速直接保證。
